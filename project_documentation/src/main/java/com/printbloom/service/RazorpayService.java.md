# `RazorpayService.java`

## 1. Purpose
This service acts as the gateway to the Razorpay API. It handles the highly secure operations required to generate real payment orders and mathematically verify that a payment was actually successful and not forged by a malicious user.

## 2. Key Concepts

### JSON Objects
Razorpay's API expects data to be sent as JSON. This service uses `org.json.JSONObject` to easily build JSON objects in Java before sending them out over the internet.

### HMAC-SHA256 Signatures
When a payment succeeds, Razorpay sends the frontend a secret signature. The frontend passes that to our backend. Our backend uses our private `keySecret` to perform complex math (`Utils.verifyPaymentSignature`) on the data. If the math result matches the signature perfectly, we know with 100% certainty the payment is real.

## 3. Code Walkthrough

1. **Mocking/Testing Mode**:
   - Look at `if ("rzp_test_placeholder_key_secret".equals(keySecret))`.
   - If the developer hasn't put in real Razorpay keys yet, this service goes into "Mock Mode". It just generates fake UUIDs and always returns `true` for verification so developers can test the app without spending real money.

2. **`createRazorpayOrder(Double amount)`**:
   - Razorpay requires money to be measured in its smallest unit (Paise, not Rupees). So it multiplies the Rupee amount by 100.
   - It creates a JSON request with the `amount`, `currency` (INR), and a random receipt ID.
   - It calls `razorpayClient.orders.create()` to send the request to Razorpay servers.
   - It returns the official `order_xxxxxx` ID generated by Razorpay.

3. **`verifySignature()`**:
   - Takes the three pieces of proof from the frontend (`orderId`, `paymentId`, `signature`).
   - Packages them into a JSON object.
   - Uses Razorpay's official Java SDK (`Utils.verifyPaymentSignature`) to check the math.
   - Returns `true` if the payment is valid, `false` if it is fake or failed.
