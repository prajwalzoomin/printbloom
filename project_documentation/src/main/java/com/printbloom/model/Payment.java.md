# `Payment.java`

## 1. Purpose
This is a **Database Entity**. Every time you see a class annotated with `@Entity`, it means this Java class is a direct representation of a table in the MySQL database. Specifically, this class represents the `payments` table. Each object of this class is a single row in that table.

The `Payment` class stores the official record of a successful (or failed) transaction from Razorpay.

## 2. Key Concepts

### `@Entity` and `@Table`
- **`@Entity`**: Tells Spring Data JPA to treat this class as a database model.
- **`@Table(name = "payments")`**: Explicitly names the table in MySQL.

### Primary Key
```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```
Every database table needs a unique identifier for each row (a Primary Key). `@Id` marks this variable as the primary key. `GenerationType.IDENTITY` tells the database to automatically generate a new, unique number (1, 2, 3, etc.) for every new payment saved.

### `@OneToOne` Relationship
```java
@OneToOne
@JoinColumn(name = "print_order_id")
@JsonIgnore
private PrintOrder printOrder;
```
This is a crucial concept. In relational databases, tables are linked together. This annotation tells Spring that exactly **one** `Payment` belongs to exactly **one** `PrintOrder`. It creates a column named `print_order_id` in the `payments` table to store this connection. 
`@JsonIgnore` is added so that when this object is converted to JSON to send to the frontend, it doesn't accidentally try to print the entire linked `PrintOrder` inside it (which could cause an infinite loop).

## 3. Code Walkthrough

The class contains fields to store the vital proof of payment:
- **`razorpayOrderId`**: The order ID generated by Razorpay.
- **`razorpayPaymentId`**: The specific transaction ID after the user actually pays.
- **`razorpaySignature`**: The cryptographic proof that the payment is legitimate.
- **`paymentStatus`**: Uses the `PaymentStatus` enum (e.g., `SUCCESS`).
- **`createdAt`**: A timestamp of when the payment occurred.

The rest of the file consists of standard Java Getters and Setters to allow reading and writing these fields.
